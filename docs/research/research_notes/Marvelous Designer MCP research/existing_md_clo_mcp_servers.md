## 1. Which Marvelous Designer or CLO3D MCP servers exist, and what does each do?

### Takeaway
Three MD MCP servers exist besides md-mcp (ysk424, its fork-like derivative Laboon2501, and dcc-mcp), and about eight CLO3D servers (Ubani-Studio plus derivatives, and independents). All are 2026 hobby/community projects with 0–37 stars, none official, none on PyPI/npm or the MCP registry. The two most advanced are **Laboon2501/MarvelousDesigner-MCP** (MD 2026.0.315, the same build as md-mcp: seam readback from pattern JSON, arrangement offsets, checkpoints, an operation journal, and a non-blocking timer listener) and **ttiimmaacc/mcp-for-clo3d** (CLO 2025.2, C++ SDK plug-in: seam-to-line mapping with twist detection, arrangement-relative placement, images returned to the model, and capture of CLO's modal dialogues).

### Inferences
- Every project independently hit the same wall md-mcp did: CLO/MD Python runs only on the GUI thread and background threads starve. Four solutions exist: block the GUI (ysk424, md-mcp, marcoleder), a native timer callback (Laboon2501 on MD via `SetTimer` from ctypes; adriendelmas in CLO), a C++ plug-in with a Qt server or message window (Lilbonner, ttiimmaacc; **not available in MD**, whose loader only takes `.py`), or an external auto-clicker (xenico100). Laboon2501's `SetTimer` route is the only one measured on MD 2026.0.315. md-mcp's P0 bug (listener outlives MD's window) and AGENTS.md's "That Run never finishes, and must not" premise should be re-tested against it, because Laboon2501 reports that the plug-in run returns at once and MD keeps serving.
- md-mcp's roadmap P1.1 (seam ledger from `ExportPatternJSON`'s `SeamLinePairGroupList`) has already been implemented by Laboon2501 against the same MD build, which confirms the field names (`PairList`, `First`/`Second`, `ShapeID`, `Direction`, `LengthParam`). ttiimmaacc's CLO version adds the two things worth copying: coverage per line and twisted-seam detection from paired ends.
- MD 2026.0.315 appears to expose `SetArrangementPosition` and `GetArrangementOfPattern` with `ArrangementOffsetX/Y/Z` (from Laboon2501's code). CLO also has `SetArrangementOrientation` and `SetArrangementShapeStyle`. A `md_api("Arrangement")` search would show whether MD has the latter two, which together are the closest any project gets to a 3D transform.
- ttiimmaacc's dialogue watcher is the only prior art that gets the host's on-screen errors back to the caller. MD and CLO share a Qt codebase and SDK (per Laboon2501's C++ README), so the same UI Automation approach may read an MD message box such as "pattern boundary is intersected while meshing". This is unverified for MD, and it would not catch messages MD prints only to a status bar or log.
- md-mcp's tool count (8) sits well below the 42 to 170 tools in these projects. Glama marked Laboon2501 down on tool count and disambiguation (2/5 each), which suggests that very large typed surfaces cost the model clarity.

## 3. Automation plugins that solve placement, seam auditing, lining, batch sewing or pattern import

### Takeaway
Outside the MCP servers, MD/CLO automation is mostly batch I/O (load → simulate → export, variation generators, Blender bridges). The relevant prior art is a pair of agent-oriented pattern pipelines (adriendelmas/pattern-making-skill with clo3d-mcp-extended; gigichengnc/clo-automation), which push seam identity upstream of the host, plus GUI auto-sewing features in CLO and Style3D. Nobody has published an MD lining generator, a seam remover or a DXF/GarmentCode/FreeSewing → MD importer with auto-sewing.

### Cited Findings
- adriendelmas/pattern-making-skill (MIT, created 2026-10-08, last push 2026-10-10): an agent skill whose single dependency-free `pattern.py` drafts blocks from measurements, "checks that seams match after each step", exports 1:1 SVG, DXF and `clo3d_<size>.json` "with exact Bezier curves and named edges"; with clo3d-mcp-extended "the agent drafts the pattern, sends the pieces to CLO3D with one CLO3D line per pattern edge, sews them by edge name, places them on the avatar and simulates"; "The agent never computes coordinates in its head" — [repo](https://github.com/adriendelmas/pattern-making-skill); [GitHub API](https://api.github.com/repos/adriendelmas/pattern-making-skill)
- gigichengnc/clo-automation (student project, August 2026): DXF generator with stable pattern/edge IDs plus a "CLO AutoSewing" state machine that reconciles garment semantics with CLO and sews "verified topology"; principles: "Do not guess garment geometry. Ambiguity is a safe-stop condition"; "Validate topology, not only counts" — [README](https://github.com/gigichengnc/clo-automation). Its KNOWN_ISSUES P0: "13 patterns + 9 sewing groups … does not prove that the intended pattern edges are connected to the intended partners"; "MockBackend success does not imply RealBackend compatibility" — [KNOWN_ISSUES.md](https://github.com/gigichengnc/clo-automation/blob/main/KNOWN_ISSUES.md)
- Ubani-Studio/clo3d-garment-generator: turns one base `.zprj` into many fabric/colour variants, writing a 3D snapshot and FBX per variant; "CLO's Python API has no call to add zips, buttons, elastic, or lacing" — [repo](https://github.com/Ubani-Studio/clo3d-garment-generator)
- lupin4/MD_Tools (February 2026): MD scripts to load `.zprj`, simulate and export USDA, batch over a folder, and print per-piece physics — [repo](https://github.com/lupin4/MD_Tools)
- cestnimaa/blender-marvelous-bridge v1.2.1 (2 stars, pushed 2026-10-10): session-folder round trip between Blender and MD via OBJ/Alembic with `bridge.json`/`result.json` manifests; "not pretend real-time live sync" — [repo](https://github.com/cestnimaa/blender-marvelous-bridge)

### Inferences
- The strongest pattern in the prior art is to compute the pattern and its named edges outside the host, then sew by edge name and verify the topology against that plan. That is roadmap P2.1 (seam plan: validate, then apply), and two independent projects reached the same design.

## 4. CLO, Style3D and Browzwear API surfaces as comparison points

### Takeaway
CLO's API (same family as MD's, 964 entries in seven modules on CLO 2026.1 against MD's 688 in six) is ahead of MD in exactly the areas md-mcp lacks. It has arrangement orientation and shape style, `ExportPatternJSON` seam-line IDs designed for reconstruction (V11.0.0, August 2026), `GetPatternOnBodyDetails`, the `ReDrape3DArrangement` re-introduction, and warning routing in place of blocking message boxes (V11.0.0). Even so, no CLO version has a seam-delete call or a free 3D transform. Browzwear's API is gated, and Style3D has no public API.

### Cited Findings
- CLO API V11.0.0 (August 2026): `ExportPatternJSON` now includes "per-pattern boundary/seam line IDs and existing SeamLine Pair Group relationships, so seam line pairings can be fully reconstructed from the exported JSON via `AddSeamlinePairGroup`"; new `MergeSewnPatterns` and `GetPatternOnBodyDetails` ("query on-body placement details of a pattern"); `ReDrape3DArrangement` "available again" after removal in V10.0.3; C++ API `qInfo()`/`qWarning()` messages routed to the Python Code Editor result panel "so API warnings are visible"; "Removed direct MessageBox calls from CloApi error paths … preventing scripts from hanging in Headless mode and in the Python Code Editor" — [CLO changelog](https://developer.clo3d.com/changelog.html)
- CLO API history: Get/SetArrangement (v3.2.0, December 2021); Get/Set Pattern Piece Position, Set Pattern Piece Move, Layer Clone Pattern Piece Position/Move (v4.0.0, June 2022); `bMoveGarment`/`bAddArrangementPoints` import options (v4.0.3); seamline pair group APIs `AddSeamlinePairGroup`, `GetSeamlinePairGroupListInPattern`, `GetSeamlinePairGroupCount`, `GetSeamlinePairGroupName`, `GetSeamlinePairGroupIndexFromName` (4.3.2, January 2024); Get/SetArrangementPoint fix (V6.0.1); `MovePatternPoint` fixes (V8.0.3, V9.0.0, V9.1.1); latest V11.0.0, August 2026. No changelog entry adds seam deletion — [CLO changelog](https://developer.clo3d.com/changelog.html)
- CLO SDK calls used for placement: `SetArrangementOrientation`, `SetArrangementPosition(pattern, x, y, offset)`, `SetArrangementShapeStyle` — [ttiimmaacc CloMcpPlugin.cpp](https://github.com/ttiimmaacc/mcp-for-clo3d/blob/main/cpp_plugin/CloMcpPlugin.cpp)
- CLO 2026.1.224 Python API: 964 public entries across seven modules — [larpingvibecoder VALIDATION.md](https://github.com/larpingvibecoder/clo3d-mcp/blob/main/docs/VALIDATION.md)
- Official MD API docs ("Marvelous Designer API 0.1") list EXPORT_API, IMPORT_API, PATTERN_API, FABRIC_API, UTILITY_API and **REST_API**, with a changelog only from MD 2024.2.189 to 2025.1.201 and "API Scenario" pages (Animation, Simulation, Pattern, Substance) — [MD developer docs](https://developer.marvelousdesigner.com/); [MD changelog](https://developer.marvelousdesigner.com/changelog.html). This conflicts with md-mcp's measurement that 2026.0.315 has no `REST_API` module (md-mcp README).
- Browzwear VStitcher API: C functions auto-ported to Python and C# (`BwApiGarmentCreate` → `BwApi.GarmentCreate`); plug-ins described by `plugin.json` (identifier, type, main, `bw-api` dependency, URL `white_list`) — [Browzwear help](https://help.browzwear.com/en/articles/13066096-understanding-vstitcher-api). Access "is limited to authorized users" — [browzwear.com/api](https://browzwear.com/api); header files are the reference and show which operations work headless; scripts are tested in a Python Playground then run in VS-CLI (search summary) — [Browzwear help](https://help.browzwear.com/en/articles/13553151-how-to-start-working-with-vstitcher-engine-vs-cli); a developer blog says little public information exists beyond the official docs — [Theodo blog](https://blog.theodo.com/2023/04/browzwear-tips-and-tricks)
- Style3D: no public developer API documentation found; Style3D Simulator documents exporting component parameters to config files for a "clothing creation → ClothRig → batch solving" pipeline (search summary) — [Style3D help](https://help.style3d.com/simulator/en/bdd4)

### Inferences
- MD and CLO share an SDK lineage (Laboon2501's C++ README; identical module names). CLO's V11.0.0 changes (warning logging, no MessageBox in error paths, seam IDs in pattern JSON) may arrive in a later MD build. MD 2026.1 (August 2026) is the candidate to check, because it was released in the same month as CLO V11.0.0. This is speculative: MD's public API changelog stops at 2025.1.201.
- The CLO V11.0.0 note confirms what md-mcp observed: API errors raise blocking message boxes and the warnings never reach the script. CLO's fix is to route them through `qWarning()` to the editor and log. If MD 2026.0.315 also writes `[Python]` warnings to a log file, that file is a cheap error channel worth looking for (md-mcp roadmap P0.2).
- Neither CLO nor Browzwear documentation (as far as visible) shows a seam-delete call. Every project falls back on checkpoint-restore and rebuild.

### Gaps
- Could not see Browzwear's header files or any sewing, transform or snapshot functions (gated).
- Did not verify which of CLO's arrangement calls exist in MD 2026.0.315. This needs `md_api`, which was out of scope for this research.
- Could not determine whether MD 2026.1 includes CLO V11.0.0's error-path changes.

### Inferences
- What to copy, in order of payoff for md-mcp's roadmap:
  1. Laboon2501's `SetTimer` non-blocking listener, which is measured on the same MD build and bears on P0.0 and the never-ending Run.
  2. ttiimmaacc's dialogue watcher (P0.2).
  3. ttiimmaacc's seam ledger semantics (coverage plus twist detection) on top of Laboon2501's JSON decode (P1.1).
  4. ttiimmaacc's `capture_3d`/`view_patterns` pair, which returns a 2D board image with numbered lines and coloured seams, not just 3D views (P0.3, P1.4).
  5. Arrangement offset/orientation/shape-style calls, if MD has them (P3).
  6. Laboon2501's operation journal with UNKNOWN status and no blind retry, and its refusal to choose "the nearest-looking edge".
  7. Laboon2501's local index of the official MD docs and scenarios (`search_md_docs`), which complements md-mcp's `notes.py`.
- What to avoid:
  - Background-thread listeners (Ubani's original never answered).
  - Mock-only validation presented as working (dcc-mcp, Ubani, gigichengnc all warn about it).
  - Count-based success.
  - `ExportSnapshot3D`-style calls that open dialogues; ttiimmaacc switched to `ExportThumbnail3D` for this reason. md-mcp uses `ExportSnapshot3D` and should check that MD does not open a dialogue there.
  - Tool explosions of 100 or more tools.
  - Publishing to PyPI as `md-mcp`, a name that is already taken.
- Lead for P4.3 (two-sided colour): Laboon2501 sets BACK/SIDE colours after unlinking with `SetUseSameMaterialAsFront`/`SetUseSameColorAsFront(..., False)` and claims verification on 2026.0.315. md-mcp's note says writing side 1 crashed MD, so the ordering may be what matters. This should be tested with a checkpoint.
- Lead for geometry readback: `GetClothPositions` exists in MD but returned an empty list from Python in Laboon2501's test. ttiimmaacc uses it successfully from C++ in CLO. md-mcp's OBJ-export route stays necessary unless a different overload works.
